# VulpeLabs 专属卡密邮箱

客户入口 `/timed/`，管理员卡密生成入口 `/timed/admin.html`。现有管理员邮箱和 Vue 管理界面保留。

## 规则

- 首次输入账号、至少 12 位密码和未使用卡密注册。客户账号与旧邮箱系统账号分开。
- 一张卡只能兑换一次。有效期加 600 秒，按 `max(当前到期时间, 当前时间) + 600` 计算。
- 每次兑换将新建名额**重置为 20**，不累加名额。旧邮箱不占新一轮名额。
- 邮箱和邮件归原账号所有。到期停止创建、阅读和收件；续时恢复已有邮箱访问。
- 新地址使用 192 位随机值，创建时检查永久地址历史表；迁移会导入现存旧邮箱，此后旧邮箱被删除也不会丢失地址历史。新地址永久保留，数据库禁止删除或重新分配。迁移之前已从旧系统物理清除的地址无法追溯，但随机地址碰撞概率极低。
- 客户没有发件接口。收件不进入旧公共邮件查询、附件、转发、AI 或 webhook 流程。
- 一个账号最多一个有效登录会话，新登录注销旧会话。账号隔离不等于自然人身份验证，请勿分享账号密码。
- 单封邮件不超过 1 MiB，正文最多 200,000 字符；展示最近 100 封（更早邮件仍保留）。HTML 转文本显示，附件仅显示名称，暂不支持下载。

## 部署到现有 Cloudflare Worker

无需添加付费服务。仍受 Cloudflare 当前免费用量和存储限制，邮件长期保留会消耗 D1 空间；不自动购买或升级套餐。

1. 在 GitHub 仓库 Actions Variables 中设置 `TIMED_MAIL_ENABLED=true` 和 `TIMED_MAIL_DOMAIN=getvulpe.com`（必须是现有 Email Routing 已接入此 Worker 的收件域名）。
2. 合并代码到 main。现有部署 workflow 会先运行测试，再通过 D1 migrations 建表，然后部署 Worker 和页面。数据库已有正常初始化的 `account` 表是前提。
3. 本仓库当前使用 Cloudflare Git 自动构建，生产部署命令设置为 `pnpm run deploy`。它先运行测试、执行 D1 migrations，再发布 Worker；`wrangler.toml` 已配置 getvulpe.com 和现有 cloudmail 数据库、KV、R2 绑定。不要直接执行仓库默认 `pnpm test`，它是旧测试环境部署命令。
4. 打开 `/timed/admin.html`，用现有 `env.admin` 对应账号登录，生成卡密并保存文本文件。数据库仅存 SHA-256 摘要，卡密原文无法找回。
5. 在客户入口使用卡密注册，创建邮箱，用外部真实邮箱发送测试邮件，确认收件。测试不会自动对外发送邮件。

默认未设置 `TIMED_MAIL_ENABLED` 时功能关闭；新增代码不会改变旧收件路径。启用后若需临时停止，应保留代码并将变量设为 false；已有数据保留。不要将有客户使用后的版本直接回退到不含隔离逻辑的旧代码，否则旧 catch-all 可能接收这些地址的邮件。

## 验证

Node 24：`cd mail-worker && node --test test/timed.test.mjs`。

测试覆盖一次性卡密、名额耗尽、有效期叠加、过期续时、邮箱不可重新分配、旧账号地址冲突、并发争用、客户隔离、CSRF、登录轮换、无发件 API、纯文本收件、大小限制和到期拒收。

新功能使用独立的 `timed_*` 表和 HttpOnly Secure SameSite=Strict cookie；不接受旧 JWT 作为客户凭据。数据库触发器与 D1 事务控制卡密和配额，页面倒计时仅为展示。请通过 HTTPS 使用。
